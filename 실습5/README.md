## 문제 한 줄

이미지마다 **어떤 노이즈가 얼마나 실렸는지 모른 채** 하나의 네트워크로 4종을 전부
지워야 한다. 종류별로 최적 필터가 정반대다 — salt & pepper 에는 median 이,
gaussian 에는 mean/adaptive 가 맞다.

## 데이터

`dataset/` (1.9GB, git 미포함). 전부 `.npy`, float32, 256×256, 값 범위 대략 [0, 1].

| 폴더 | 장수 | 내용 |
|---|---|---|
| `train/` | 7,268 | clean. noisy 는 학습 중에 합성한다 |
| `val/` | 100 | clean. 검증용 noisy 는 파일명 기반 고정 seed 로 합성 |
| `test_noise_only/` | 100 | **손상 이미지** (+ `noise_meta.json`) |
| `test_label/` | 100 | test 정답. **제공된다** |

### 노이즈 4종

이미지마다 4종 중 하나를 균등하게 고르고, 아래 범위에서 σ 를 균등하게 뽑는다.

| 종류 | σ 범위 | 성질 |
|---|---|---|
| `gaussian` | 0 – 0.1 | `x + N(0, σ)` |
| `rician` | 0 – 0.15 | `\|x + N(0,σ) + iN(0,σ)\|` — 어두운 영역에서 값이 위로 들린다 |
| `uniform` | 0 – 0.2 | `x + U(-σ, σ)` |
| `salt_and_pepper` | 0 – 0.2 | 픽셀의 σ 비율을 0 또는 max 로 덮어쓴다 — **임펄스** |

`test_noise_only/noise_meta.json` 에 test 100장의 종류와 σ 가 다 적혀 있다.
이 저장소의 코드는 그 정보를 **표를 종류별로 쪼개는 데만** 쓰고 복원에는 쓰지 않는다.
채점 세트에 메타가 없을 수도 있고, 무엇보다 종류를 모르고도 되는 게 더 강한 결과다.

## 넘어야 할 기준선

배포된 예시 로그(`log_denoising_example/00012_train`, DnCNN 10 epoch)의 test 성적.

**PSNR (dB)**

| noise | n | noisy | DnCNN | mean | median | adaptive |
|---|---|---|---|---|---|---|
| gaussian | 25 | 27.668 | 32.044 | 26.316 | 27.382 | 30.078 |
| rician | 25 | 24.079 | 28.900 | 23.669 | 24.080 | 27.046 |
| salt_and_pepper | 25 | 17.304 | 29.692 | 23.196 | 28.496 | 21.164 |
| uniform | 25 | 29.631 | 31.406 | 26.263 | 26.779 | 30.521 |
| **ALL** | 100 | 24.671 | **30.510** | 24.861 | 26.684 | 27.202 |

**SSIM ALL**: noisy 0.6659 · DnCNN **0.8950** · mean 0.7615 · median 0.8076 · adaptive 0.7919

여기서 읽히는 것:

- **salt & pepper 가 문제다.** 입력이 17.3 dB 로 혼자 7~12 dB 아래고, conventional
  중에서는 median 만 (28.5 dB) 통한다. mean 은 23.2, adaptive 는 21.2 로 오히려
  gaussian 때보다 못하다. 임펄스는 "작은 흔들림"이 아니라 "몇 픽셀이 통째로 거짓말"이라
  평균 계열이 그 거짓말을 이웃에 퍼뜨린다.
- **conventional 은 전체 평균에서 입력을 거의 못 넘는다.** mean 24.86 vs noisy 24.67.
  종류를 모르는 채 하나의 필터를 고정하면 이런 결과가 된다.
- **DnCNN 은 그 문제를 통째로 우회한다.** 종류별로 다르게 반응하도록 학습되니까.

## 접근

배포 코드와 **같은 데이터 · 같은 노이즈 합성 · 같은 지표**를 쓰고, 학습 쪽만 손봤다.

| 바꾼 것 | 이유 | 결과 |
|---|---|---|
| **Charbonnier** loss (L2 → smooth L1) | L2 는 s&p 의 극단값 몇 픽셀에 gradient 가 끌려간다 | 채택 |
| **cosine LR, 40 epoch** (기본 10 epoch, plateau×0.88) | 10 epoch 에서는 감쇠가 사실상 안 걸린다 | 채택 |
| **patch 128 랜덤 크롭 + rot90** | 크롭 자체가 증강이고 step 수도 2배가 된다 | 채택 |
| 추론 시 **8× self-ensemble** | dihedral 8종으로 추론해 되돌려 평균. 학습 비용 0 | **+0.30 dB** |
| 입력에 **median 3×3 채널 추가** (`DnCNNPlus`) | s&p 에서 median 이 mean 을 5 dB 앞선다. "이미 임펄스가 지워진 버전"을 같이 주면 유리할 것이라 봤다 | **기각 (−0.39 dB)** |

**구조는 배포된 DnCNN 그대로가 최선이었다.** 기준선 대비 개선은 전부 학습 절차에서 나왔다.

### median 채널 가설은 기각됐다

s&p 입력이 17.3 dB 로 혼자 10 dB 아래고 고전 필터 중 median 만 통하니(28.5 vs mean 23.2),
median 결과를 두 번째 입력 채널로 주면 도움이 될 것이라는 가설이었다. ablation 결과:

| | 전체 | s&p 구간 |
|---|---|---|
| 순정 DnCNN | **34.13 / 0.9445** | **35.95 / 0.9842** |
| + median 채널 | 33.75 / 0.9424 | 34.74 / 0.9821 |

**넣은 이유였던 s&p 에서 오히려 1.21 dB 를 잃었다.** median 이 임펄스를 지우면서 미세
계조도 뭉개고, 네트워크가 그 뭉개진 채널에 일부 의존하게 된 것으로 보인다. 17층 3×3 이면
임펄스는 스스로 처리할 수 있었다 — 네트워크의 능력을 과소평가하고 불필요한 유도 편향을
넣은 셈이다. ablation 을 안 돌렸으면 0.39 dB 를 손해 본 채 "median 채널 덕분"이라고
발표할 뻔했다.

### 되지 않은 것 — σ 게이트

입력이 이미 50~62 dB 인 이미지에서는 모델이 손해다 (100장 중 8장). 정답을 보고 매번
유리한 쪽을 고르면 **+0.52 dB**. 그런데 σ̂ 로는 그 8장을 못 고른다 — MAD 추정기가
이미지의 미세 질감을 노이즈로 착각해, 실제 σ=0.001 인 이미지를 0.037 로 추정한다.
임계값을 어디에 두든 손해였다 (τ=0.004 에서 −0.017 dB, τ=0.02 에서 −2.89 dB).

blind 상태라는 제약이 실제 비용을 발생시킨다는 구체적 증거다. `analyze_gate.py` 로 재현된다.

## Label-free 파이프라인 (가산점)

clean 이미지를 loss 에 **한 번도 쓰지 않고** 학습한다 (Noise2Void, `train_n2v.py`).

어떤 픽셀의 값을 주변 값으로 덮어써 입력에서 지운 다음 그 자리를 맞히게 하고, 정답으로
덮어쓰기 전의 **noisy 값**을 준다. 노이즈가 픽셀마다 독립이면 주변에서 그 픽셀의 노이즈를
알아낼 방법이 없으니, 네트워크가 맞힐 수 있는 건 구조뿐이다.

우리 노이즈 4종은 전부 픽셀 독립이라 전제를 만족한다. 다만 L2 loss 는 조건부 **평균**을
학습하므로 노이즈 평균이 0 이어야 하는데 **s&p 는 0/max 로 덮으니 아니고, rician 은
절댓값 때문에 위로 들린다.** 그래서 L1 을 쓴다 — 조건부 **중앙값**은 임펄스에 끌려가지 않는다.

**체크포인트 선택도 label-free 로 한다.** val noisy 의 마스킹 loss 로 고른다. clean 기반
PSNR 로 고르면 파이프라인 전체가 label-free 가 아니게 되기 때문이다.

```
label-free · train 7,268장 (clean 0장, test 무접촉)   PSNR 31.38   SSIM 0.9056
배포 기준선 (clean 7,268장 supervised)                PSNR 30.51   SSIM 0.8950
```

**정답을 한 장도 안 쓰고 배포 기준선을 넘었다** (+0.87 dB / +0.0106).

### 학습 데이터를 어디서 가져올 것인가

label-free 는 noisy 이미지만 있으면 되므로 출처가 두 가지다.

| | 구조 | 학습 데이터 | test 입력 | PSNR | SSIM |
|---|---|---|---|---|---|
| A | DnCNN | `test_noise_only` 100장 | **사용** | 30.95 | 0.8992 |
| B | DnCNN | train 에서 합성한 noisy 7,268장 | 미사용 | 30.35 | 0.8923 |
| **B** | **DRUNet** | train 에서 합성한 noisy 7,268장 | **미사용** | **31.38** | **0.9056** |

세 실험으로 두 축이 분리된다.

```
데이터 축  A → B(DnCNN)      구조 고정, 100장 → 7,268장   −0.60 dB
구조 축    B(DnCNN) → B(DRUNet)  데이터 고정, 수용영역 확장   +1.03 dB
```

**100장이 7,268장을 이긴다.** `--source train` 은 매번 노이즈를 새로 뽑으므로 모델이
일반적인 디노이저를 배워야 한다. 반면 `--source test` 는 그 100장을, 그 노이즈 실현
그대로 반복해서 본다 — Noise2Void 가 원래 겨냥한 설정이고, 일반화를 포기하는 대신
그 이미지에서 최대치를 뽑는다.

A 는 복원할 이미지 자체로 학습하는 것이라 label-free 의 취지에는 맞지만,
**supervised 와 공정하게 비교할 수 없다** — supervised 는 test 입력을 본 적이 없다.
B 는 test 를 전혀 건드리지 않으므로 기준선과 나란히 놓을 수 있고, 성능도 더 좋다.
발표에는 B 를 대표값으로 쓰고 A 는 함께 보고한다.

> **기록 — 맞는 결론을 틀린 근거로 주장했다.** 처음 B 를 돌려 보고 "데이터를 73배
> 늘려도 3 dB 나쁘다, 평가 대상에 적응하는 쪽이 유리하다"고 결론지었다. 결론의
> **방향은 맞았지만**(30.95 vs 30.35) 근거는 못 쓸 것이었다. 그 실행은 fp16 + lr 3e-4
> 로 DRUNet 을 NaN 으로 발산시킨 것과 같은 조합이었고, 진단 PSNR 25.9 에서 하락 중이었다.
> 제대로 돌리니 30.35 가 나온다 — 4.4 dB 차이다. 고장난 실험에서 우연히 같은 방향의
> 답이 나왔을 뿐이고, 그때 멈추지 않았다면 반대 결론을 냈어도 이상하지 않았다.

### median 채널은 여기서도 기각됐다

| N2V 구조 (test 100장 학습) | PSNR | SSIM |
|---|---|---|
| 순정 DnCNN | **30.95** | **0.8992** |
| + median 채널 | 30.08 | 0.8882 |

supervised 에서 −0.39 dB, label-free 에서 −0.87 dB. **학습 방식과 무관하게 일관되게
손해**다. 한 번의 우연이 아니라 구조 자체의 문제라는 증거다.

`--source train` (train clean 으로 noisy 를 합성해 그 noisy 만 학습) 도 해 봤지만 step 2000 이
최고점이고 그 뒤로 하락했다 (진단 PSNR 25.9). 데이터가 73배 많은데 3 dB 나쁘다. 평가 대상
100장에 적응하는 쪽이 일반 디노이저를 배우는 것보다 유리했다.

### 구조 — DnCNN 의 한계는 수용영역이었다

17층 3×3 은 한 픽셀을 결정할 때 **35픽셀**만 본다. 256² 이미지에서 넓은 평탄 영역의
노이즈를 판단하거나 큰 구조를 복원하려면 그보다 넓게 봐야 한다.

| 모델 | 파라미터 | 수용영역 | test PSNR | test SSIM |
|---|---|---|---|---|
| DnCNN (60ep) | 0.59M | 35px | 34.56 | 0.9489 |
| DRUNet (60ep) | 32.6M | ~180px | 36.50 | 0.9580 |
| **DRUNet (180ep)** | 32.6M | ~180px | **37.42** | **0.9609** |

같은 데이터·같은 레시피·같은 60 epoch 에서 **+1.94 dB**. 노이즈별로 보면 차이가 어디서
나는지 분명하다.

| noise | DnCNN 60ep | DRUNet 60ep | Δ |
|---|---|---|---|
| gaussian | 34.95 | 35.68 | +0.73 |
| rician | 31.28 | 31.96 | +0.68 |
| uniform | 35.22 | 35.74 | +0.52 |
| **salt & pepper** | 36.78 | **42.60** | **+5.82** |

180 epoch 에서는 salt & pepper 가 **45.01 dB** 까지 간다 (DnCNN 대비 +8.23,
입력 17.30 대비 **+27.7 dB**).

임펄스에서 격차가 압도적이다. 튀어버린 픽셀의 값을 복원하려면 주변을 넓게 봐야 하는데,
35px 창으로는 임펄스 밀도가 높을 때 참고할 성한 픽셀이 부족하다. **median 채널을 손으로
붙여 해결하려던 문제를 수용영역 확장이 제대로 풀었다** — 유도 편향을 넣는 대신 네트워크가
볼 수 있는 범위를 넓히는 쪽이 답이었다.

DRUNet 은 메모리를 오히려 DnCNN 보다 적게 쓰지만(U-Net 이라 저해상도에서 계산)
연산량이 3.4배다. 로컬 6GB 에서는 729 ms/iter 로 60 epoch 에 5.5시간, A100 에서는 **12분**이다.

**성능만이 선택 이유는 아니었다. 3일차가 더 크다.** DRUNet 은 DPIR(Plug-and-Play Image Restoration
with Deep Denoiser Prior)의 디노이저 프라이어로 설계된 구조다. 3일차의 deconvolution +
denoising 결합에서 데이터 정합 단계와 사전지식 단계를 번갈아 푸는 구조를 쓰려면,
사전지식 자리에 들어갈 디노이저가 바로 이것이다. `sigma_map=True` 로 노이즈 세기를
채널로 받는 모드도 넣어 뒀다 — 그 반복에서 매 단계 "이번엔 이만큼만 지워라"라고
지시하는 데 쓴다. 1일차는 σ 를 모르므로 blind 로 쓴다.

## Day 2 — Deconvolution

`g = h * f`. dipole 컨볼루션으로 흐려진 이미지를 되돌린다. **1일차와 같은 clean
이미지**를 쓰지만 열화가 다르고, **결론도 정반대다.**

| | Day 1 denoising | Day 2 deconvolution |
|---|---|---|
| 열화 | `g = f + n` | `g = h * f` (**노이즈 없음**) |
| 입력 PSNR | 24.67 | **7.89** |
| 고전 최고 | adaptive 27.20 | **Wiener 109.72** |
| 딥러닝 | **DRUNet 37.42** | 배포 U-Net 25.59 |
| 승자 | 딥러닝 +10 dB | **고전 +84 dB** |

입력은 2일차가 훨씬 나쁜데 결과는 훨씬 좋다. **노이즈가 없으면 역연산이 거의
정확하기 때문**이다 — 이산 격자에서 D 가 정확히 0 인 점이 없고 분모에 1e-8 도
들어 있어 1/D 가 기계 정밀도까지 통한다. 신경망이 해석적 역함수를 이길 수 없다.

Day 3 강의자료가 경고한 *QSM Challenge 2.0 에서 고전 기법이 딥러닝을 이긴 사례* 가
여기서 그대로 재현된다. 배포 예시 로그의 K 스윕이 `1e-4` 에서 멈춰 있어 격차가
16.7 dB 로만 보이지만, 더 낮추면 84 dB 다.

### 제출값

```
PSNR_total 109.86    SSIM_total 1.0000
```

`test_deconv_only` 100장, **직접 역산**(Wiener K→0, 메타의 B0 방향 사용).

`K ≤ 1e-13` 부터는 값이 변하지 않는다. 알고리즘의 한계가 아니라 **배포 파일이
float32 라서** 생기는 양자화 바닥이다 — 같은 이미지를 float64 로 직접 흐리게 만들어
되돌리면 118.54 dB 가 나온다. 그 8.7 dB 차이가 float32 양자화다.

즉 **측정치에 남아 있는 정보를 전부 되살린 상태**이고 더 잘할 방법이 없다.
발표에서는 이 숫자를 "문제를 잘 풀었다"가 아니라 **"이 문제에는 노이즈가 없어서
정확히 가역이었다"** 로 설명하는 것이 맞다.

### 배포된 test 세트

| 폴더 | 장수 | 내용 |
|---|---|---|
| `test_deconv_only` | 100 | 전부 B0 = (0, 1). 노이즈 없음 |
| `test_deconv_multi` | 100 | 25장씩 4방향 (0° / 45° / 90° / 135°) |

`test_deconv_only` 는 배포 측정치와 우리 forward 가 **1.87e-07** (float32 정밀도
한계)로 일치한다. 노이즈가 없다는 뜻이기도 하다.

**`test_deconv_multi` 는 COSMOS 가 아니다.** 폴더끼리 이미지가 하나도 겹치지 않는다 —
같은 장면을 여러 방향으로 찍은 게 아니라 이미지마다 커널 방향이 다른 것이다.
여러 방향을 합쳐 0 영역을 메우는 건 불가능하고, 대신 **이미지마다 올바른 커널을
골라야 한다.**

### 방향은 측정치에서 알아낼 수 있다

`G = D·F` 이므로 |D| ≈ 0 인 magic-angle cone 에는 신호가 통과하지 못한다. 스펙트럼에서
**에너지가 비어 있는 방향**을 찾으면 그게 커널 방향이다. 메타데이터가 필요 없다.

1° 로 훑고 그 주변을 0.01° 로 다시 훑는 2단계로 **평균 오차 0.19°** 다.

### K 는 모델이 틀린 만큼을 흡수한다

```
test_deconv_only  (방향 고정, 메타)   K=1e-12  →  109.72 / 1.0000
test_deconv_multi (메타 방향)         K=1e-6   →   48.52 / 0.9935
test_deconv_multi (추정 방향)         K=1e-5   →   41.22 / 0.9838
test_deconv_multi (0° 고정)           K=1e-12  →   18.57
```

**불확실성이 클수록 최적 K 가 커진다.** 방향을 정확히 알면 1e-12, 추정하면 1e-5 다.
노이즈가 늘 때 K 가 커지는 것과 같은 구조다 — K 는 잡음이든 커널 오차든 **모델이
현실과 어긋난 만큼**을 흡수한다. 최소 K 가 항상 정답인 게 아니다.

구체적으로 얼마나 취약한지:

| | 0° | 0.01° | 0.1° | 1.0° |
|---|---|---|---|---|
| K=1e-12 | 107.4 | 53.8 | 21.1 | 9.5 |
| K=1e-6 | 54.7 | 54.1 | 44.6 | 25.5 |

`K=1e-12` 는 **0.01° 오차에 절반이 날아간다.** 그리고 45°/135° 는 방향이 정확해도
`K=1e-12` 에서 25 dB 밖에 안 나온다 — 격자와 0 영역이 맞물려 1/D 가 수치적으로
폭발하기 때문이다.

방향을 무시하고 0° 커널을 전부에 적용하면 45°/90°/135° 에서 **−11 ~ −13 dB**,
흐린 입력(7.89)보다도 나쁘다.

### 신경망을 쓴다면

입력을 무엇으로 주느냐가 핵심이다.

| `--input` | 네트워크가 하는 일 | 결과 |
|---|---|---|
| `measure` | 역연산 **전체**를 배워야 한다 (배포 방식) | 6 epoch 에 18.6 dB 에서 기어감 |
| `wiener` | 역연산은 FFT 로 끝내고 남은 국소 아티팩트만 | 200 iter 만에 loss 17배 낮음 |

dipole 디컨볼루션은 원리적으로 **전역 연산**이다 (주파수 영역의 1/D 곱하기).
한 픽셀을 복원하려면 이미지 전체를 봐야 하는데 DnCNN 의 수용영역은 35px, U-Net 도
수십 px 다. `measure` 를 그대로 넣는 건 구조적으로 불가능한 요구다.

1일차에서 DRUNet 이 이긴 이유(수용영역 35 → 180px)와 같은 축이고, 여기서는 그
정도로도 부족해서 **아예 FFT 로 넘기는** 것이 답이다.

## 다음 — Day 3

`g = h * f + n`. 노이즈가 들어오는 순간 2일차의 답(작은 K)은 못 쓰게 된다.

```
σ=0      K=1e-12  →  118.5 dB
σ=1e-3   K=1e-12  →    7.9 dB     흐린 입력과 같음
```

그때 비로소 학습이 필요해지고, 1일차의 디노이저와 2일차의 역연산을 **번갈아 쓰는**
구조(plug-and-play)가 답이 된다. 1일차에 DRUNet 을 고른 이유가 이것이다 —
DPIR 의 디노이저 프라이어로 설계된 구조라 그 자리에 그대로 들어간다.
