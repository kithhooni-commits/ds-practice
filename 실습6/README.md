## 원래 아이디어와 이번 데모의 범위

원래 목표는 **4인 온라인 대전 + 호스트 뷰 + 얼굴 사진 학습 기반 3D 복원 아바타**였다. 둘 다 이번
데모엔 없다.

- **4인 동시 온라인 대전**은 여러 브라우저를 실시간으로 연결하는 시그널링/릴레이 서버가 있어야
  하는데, 지금까지처럼 정적 HTML 한 장(GitHub Pages)으로는 못 만든다.
- **얼굴 사진 학습 → 3D 복원 아바타**는 사람마다 새로 학습해야 하는 연구 수준 3D 재구성이라, "5일간
  새 데이터·학습 없음"이라는 이번 과제 규칙과 맞지 않고, 이 개발 환경엔 GPU도 없다.

그래서 이번 데모는 **1인용, 상대는 AI(단순 실루엣), 핵심 루프(자세 인식 → 기술 판정 → 공격/방어 →
HP)를 실제로 동작하게 만드는 것**에 집중했다. 이게 되면, 멀티플레이는 "이 판정 결과를 네트워크로
주고받는" 훨씬 작은 다음 단계가 된다.

## IN → OUT

```
웹캠 팔·머리 관절 시퀀스  →  기술 판정(잽/훅/어퍼컷 + 더킹/위빙) + 양측 HP + 승패
```

## 아이디어

MediaPipe **Pose Landmarker**(브라우저, 상반신 포함 33개 관절)로 어깨·팔꿈치·손목·코 좌표만
가져다 쓰고, 기술 판정은 전부 직접 짠 규칙 기반 로직이다.

- **펀치 발동 조건**: 팔꿈치 각도는 "가드 자세인지"만 판정한다(< 100°). 실제 발동 트리거는
  **손목 속도**가 임계값을 넘는 순간이다 — 훅은 팔꿈치를 편 채로 치는 게 아니라 굽힌 채로 휘두르기
  때문에, "팔꿈치가 완전히 펴져야 펀치"로 잡으면 훅을 영영 못 잡는다(개발 중 직접 겪은 버그, 아래
  참고).
- **기술 분류**: 가드 자세로 들어간 시점의 손목 위치를 기준점으로 잡고, 발동 순간까지의 변위
  (dx, dy)의 방향으로 잽/스트레이트·훅·어퍼컷을 나눈다 — 수직 위쪽 이동이 크면 어퍼컷, 수평 이동이
  크면 훅, 나머지는 잽/스트레이트.
- **방어**: 코 좌표의 느린 이동평균(EMA)을 "정면 자세" 기준으로 삼고, 상대 공격 예고 구간 동안 코가
  기준보다 충분히 아래로 내려가면 더킹, 좌우로 벗어나면 위빙으로 판정한다. 상대의 스트레이트는
  더킹으로, 훅은 위빙으로 막아야 한다.
- **AI 상대**: 1.8~3.2초마다 무작위로 스트레이트/훅 중 하나를 예고(0.75초 텔레그래프)한 뒤 판정한다.

## 구조

| 경로 | 내용 |
|---|---|
| `index.html` | 앱 전체 (HTML/CSS/JS 단일 파일, 서버·오디오 파일 불필요) |

## 사용 기술

- **관절 추출**: `@mediapipe/tasks-vision` `PoseLandmarker` (`lite` 모델, CDN, Apache-2.0), 브라우저 WASM 실행
- **기술 판정**: 팔꿈치 각도(가드 판정) + 손목 속도 rising-edge(발동 트리거) + 변위 방향(기술 분류) — 전부 규칙 기반, 학습 없음
- **방어 판정**: 코 좌표 EMA 기준선 대비 순간 이탈량(더킹/위빙)
- **오디오**: Web Audio API로 타격음·회피음·라운드 벨을 그 자리에서 합성 (파일 없음)

## 실행 방법

1. `index.html`을 HTTPS 또는 `localhost`에서 연다 (GitHub Pages 링크, 또는 로컬에서
   `python -m http.server`). `file://`로 직접 열면 카메라 권한이 막힐 수 있다.
2. "카메라 + 모델 시작" 클릭 → 카메라 권한 허용 → 모델 다운로드 대기(최초 1회, 네트워크 필요).
3. 카메라에서 상반신(어깨~손목, 얼굴)이 다 보이는 거리로 물러난다.
4. "라운드 시작" 클릭 — 60초 라운드가 시작되고 상대가 주기적으로 공격을 예고한다.
5. 평소엔 가드 자세(팔꿈치를 굽힌 채)로 있다가, 때릴 땐 빠르게 뻗기/휘두르기/올려치기 하고,
   상대 예고가 뜨면 스트레이트는 고개를 숙이고(더킹) 훅은 옆으로 피한다(위빙).
6. HP가 0이 되거나 60초가 지나면 라운드가 끝나고 통계(총 펀치, 기술별 카운트, 방어 성공률, 평균
   펀치 속도)가 남는다.

## 개발 중 잡은 버그 (테스트로 발견 — "문제 해결" 기록)

이 환경엔 실제 웹캠이 없어서, 가짜 관절 좌표를 주입하는 헤드리스 브라우저 테스트로 판정 로직을
검증했다. 그 과정에서 실제로 게임에 영향을 주는 버그 두 개를 코드를 배포하기 전에 잡았다.

1. **가드로 복귀하는 동작 자체가 펀치로 오인됨** — 손을 빠르게 원위치로 되돌리는 프레임이 "막
   가드에 들어간 순간"과 겹치면 오탐 펀치가 발동했다. → 가드 상태가 "이전 프레임에 이미 성립"했을
   때만 발동하도록 고쳤다.
2. **훅처럼 팔꿈치가 편 채로 안 끝나는 펀치는 기준점이 착지 지점으로 슬쩍 재설정됨** — 펀치가 착지한
   자세도 팔꿈치 각도가 여전히 100° 미만이면, 쿨다운이 끝나자마자 "방금 착지한 그 자리"를 새 기준점
   으로 다시 잡아버려서 다음 판정이 엉켰다. → 펀치가 발동한 직후 일정 시간(쿨다운)은 가드 재무장
   자체를 막도록 고쳤다.

두 버그 다 "논리적으론 맞아 보이는데 실제 동작 시퀀스로 돌려보니 어긋난" 경우라, 실제 웹캠 없이도
자동화된 시퀀스 테스트가 왜 필요한지 보여주는 사례다.

## 알려진 한계

- **감도·임계값(손목 속도 2.2, 더킹 0.055, 위빙 0.05)은 검증되지 않은 초기값**이다. 이 환경엔
  웹캠·GPU가 없어 실제 웹캠으로 튜닝하지 못했다 — 반드시 실제 사용 환경에서 다시 맞춰야 한다.
- **정면으로 찌르는 펀치(카메라 쪽으로)는 이미지 평면(x,y)만 보는 이 방식으로 잘 안 잡힐 수 있다** —
  Pose Landmarker의 z좌표는 신뢰도가 낮아 안 썼는데, 그 대가로 카메라와 평행하게 휘두르는 동작에
  최적화돼 있다. 몸을 살짝 옆으로 틀고 치면 더 잘 잡힐 것이다.
- 왼팔/오른팔을 동시에 빠르게 쓰는 콤보(원투 등)는 테스트하지 못했다 — 두 팔 상태는 독립적으로
  추적하지만 실전 콤보에서 서로 간섭하는지는 실제 웹캠 검증이 필요하다.
- 상대는 스트레이트·훅 두 종류만 던진다 — 어퍼컷 예고는 아직 없다(방어 로직을 "더킹=스트레이트,
  위빙=훅" 두 갈래로만 단순화했기 때문).
- 상대는 고정된 실루엣 그래픽이다 — 원래 구상이었던 실사 3D 아바타는 위에서 설명한 이유로 이번
  범위 밖이다.
