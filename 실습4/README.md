# 실습4 — 제스처 비밀번호 잠금장치

**Computer Vision Practicum** (SNU Visual Computing Lab, 지도: 조한별 / Samsung Electronics DS,
2026-08-24 ~ 08-28). 기존 오픈소스 도구를 조합해 5일 안에 "의미 있고 재미있는" 비전 앱을 만드는 팀 실습.

**웹에서 보기 →** https://kithhooni-commits.github.io/ds-practice/실습4/

## IN → OUT

```
웹캠 손 프레임 시퀀스  →  등록된 제스처 순서와 일치 여부(성공 / 실패) + 신뢰도
```

## 아이디어

MediaPipe **Hand Landmarker**(브라우저·CPU/GPU, 21개 손 랜드마크)만 기존 모델로 가져다 쓰고,
그 위에 손을 새로 학습시키지 않는다: 랜드마크 좌표만으로 6가지 제스처를 규칙 기반으로 판별하고,
사용자가 등록한 제스처 순서를 "비밀번호"로 저장해 같은 순서를 다시 보여줘야 잠금이 풀리는 인증
데모다. 서버 없이 전부 브라우저(HTML/JS)에서 돌아가므로 GitHub Pages에 올리면 발표 때 노트북
웹캠으로 바로 라이브 데모가 된다.

## 사용 기술

- **랜드마크 추출**: `@mediapipe/tasks-vision` `HandLandmarker` (CDN, Apache-2.0), 브라우저에서 WASM으로 실행
- **제스처 분류**: 21개 랜드마크의 y좌표(손가락 폄/접힘) + 거리 기반 휴리스틱(엄지)으로 직접 작성한 규칙 기반 분류기 — 학습 없음
- **시퀀스 인증**: 안정 프레임 카운터(연속 10프레임 이상 같은 제스처가 유지되면 "캡처") 기반 상태 머신, `localStorage`에 비밀번호 저장

| ✊ 주먹 | 00000 |

## 실행 방법

1. `index.html`을 HTTPS 또는 `localhost`에서 연다 (GitHub Pages 링크, 또는 로컬에서
   `python -m http.server`로 서빙). `file://`로 직접 열면 브라우저가 카메라 권한을 막을 수 있다.
2. "카메라 + 모델 시작" 클릭 → 카메라 권한 허용 → 모델 다운로드 대기(최초 1회, 네트워크 필요).
3. 등록 길이(3~6개)를 고르고 "등록 시작" → 제스처를 순서대로 보여준다.
   같은 제스처를 연속으로 쓰려면 손을 화면 밖으로 뺐다가 다시 보여줘야 한다(안정 프레임 카운터가
   재사용 여부를 판단하는 설계).
4. "해제 시도"로 같은 순서를 다시 입력해 잠금이 풀리는지 확인한다.
5. 오른쪽 패널의 통계(시도 횟수·성공률·평균 해제 시간·평균 신뢰도)와 로그 표에 모든 시도가 기록된다.

## 설계에서 정한 것

- **엄지 판별**: 손 방향(왼손/오른손, 좌우 반전)에 상관없이 쓰려고 각도 대신 `거리(엄지 끝 ↔ 소지
  뿌리) vs 거리(엄지 IP 관절 ↔ 소지 뿌리)` 비율로 판별. 정확도는 손목 각도 기반 방법보다 낮을 수
  있지만 좌우 손 구분 로직이 필요 없다.
- **같은 제스처 연속 사용**: 안정 프레임 카운터만으로는 같은 제스처를 오래 들고 있으면 여러 번
  캡처될 위험이 있어, "손이 프레임에서 사라지기 전까지는 같은 제스처를 재캡처하지 않음"으로 막았다.
  대신 같은 제스처를 연달아 쓰려면 손을 뺐다 다시 넣어야 한다.
- **신뢰도 지표**: MediaPipe가 프레임마다 주는 handedness(좌/우 손 분류) 점수를 신뢰도로 노출한다.
  "이 손이 진짜 손처럼 보이는 정도"에 가깝고 제스처 분류 자체의 정확도는 아니라는 점을 README에
  명시해 둔다.

## 알려진 한계 (수 ~ 목 개선 대상)

- 조명이 어둡거나 손이 프레임 경계에 걸치면 랜드마크가 흔들려 안정 프레임(10프레임)까지 도달하는
  시간이 길어진다.
- 위조 공격(사진, 녹화 영상 재생) 방어가 없다 — liveness 검증 없음.
- 단일 사용자·단일 손 가정. 다중 프로필이나 양손 제스처는 지원하지 않는다.
- 6가지 패턴 밖의 애매한 손 모양(예: 손가락이 반쯤 접힌 경우)은 전부 "인식 불가"로 버려진다 —
  세분화된 임계값 대신 이진 폄/접힘 판정만 쓰기 때문.
