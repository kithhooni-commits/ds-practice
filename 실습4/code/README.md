## 🥊 2. 복싱 & 전투 모션 정의

플레이어가 **실제로 할 수 있는 동작 전부**입니다. 서버가 이해하는 액션 이름과 1:1로 대응합니다.

| 분류 | 동작 | 액션 이름 | 어떻게 |
| :--- | :--- | :--- | :--- |
| **이동** | 전진 | `FORWARD` | 어깨 수평 + 앞으로 숙이기 |

### 경기 방식 — 최후 1인 생존 (LAST MAN STANDING)

**제한 시간이 없습니다.** 시계는 경과 시간(mm:ss)만 세고 경기를 끝내지 않습니다.

- 유일한 종료 조건은 **생존자가 1명**이 되는 것입니다. 판정승은 없습니다.
- HP가 0이 되면 **링에서 뒤로 쓰러지며 사라지고**, 그 파이터는
  이동·조준 대상·충돌 판정에서 모두 빠집니다 (보이지 않는 벽이 남지 않도록).
- 1인칭에는 K.O. 오버레이가 덮이고 **이동이 정지**합니다. "조작이 고장난 것"이 아닙니다 —
  좌상단 HP 바가 0인지 먼저 확인하세요.
- Host 화면의 **새 라운드 시작** 버튼을 누르면 전원 HP 100으로 부활합니다.
  등록한 얼굴은 라운드 리셋으로 지워지지 않습니다.

### 2-1. 이동 모션 (몸 기울임)

모든 지표는 **어깨폭 단위로 정규화** + **중립 자세 대비 편차**로 계산하므로,
카메라 거리·체형·해상도가 달라도 같은 임계값이 통합니다.

| 모션 | 몸 동작 | 판정 조건 | 임계값(진입/해제) |
| :--- | :--- | :--- | :--- |
| **FORWARD** | 앞으로 숙임 | 어깨 평행 + 얼굴·주먹이 **아래로** | pitch `+0.105 / +0.065` |
| **BACK** | 뒤로 젖힘 | 어깨 평행 + 얼굴·주먹이 **위로** | pitch `−0.175 / −0.115` |
| **LEFT / RIGHT** | 좌·우로 기울임 | **어깨선 자체가 기울어짐** | roll `12° / 7°` |
| **ROT_LEFT / ROT_RIGHT** | 주먹을 좌·우로 쓸기 | 어깨 평행 + **양 손목이 같은 방향으로** 이동 | shift `0.40 / 0.24` |

- **"어깨 평행"** 은 roll 절댓값이 8°(`ROLL_FLAT`) 미만인 상태입니다. 앞/뒤와 회전의 **전제 조건**이라,
  어깨가 기울어져 있으면 좌/우 스텝으로만 해석됩니다.
- 이동 속도는 강도 100% 기준 **14 units/s**(후진은 0.85배). 강도는 임계값을 넘은 만큼 비례합니다.
- 링은 `±16 units` 정사각형입니다.

> **전진이 후진보다 쉽게 걸립니다.** 4차에서는 "사람은 뒤로 조금밖에 못 젖히므로 후진을 낮게"
> 잡았는데 실사용 결과가 정반대였습니다 — 전진 신호는 얼굴·주먹·어깨폭 여러 항으로 분산되는 반면,
> 후진은 얼굴이 올라가는 **한 가지 신호**로 곧장 잡히기 때문입니다. 12차에서 뒤집었습니다.

> **회전은 제스처 1회당 최대 45°** 입니다(`ROT_LIMIT`, 속도 1.3 rad/s ≈ 75°/s).
> 제스처를 계속 유지해도 45°에서 멈추므로 제자리에서 한 바퀴 도는 일이 없습니다.
> 더 돌리려면 주먹을 중앙으로 되돌려 제스처를 끝냈다가 다시 미세요. HUD `Turn` 줄에 `nn/45deg`로 표시됩니다.

```
dirCore = 0.45·(얼굴이 어깨선 대비 내려간 정도)
        + 0.25·(주먹이 어깨선 대비 내려간 정도)          ← 방향을 결정하는 유일한 항
conf    = clamp01(|dirCore| / 0.05)                       ← 방향이 확실한가
pitch   = dirCore + conf·( 1.20·(어깨폭 증가율)           ← 부호가 dirCore와 같을 때만
                         + 0.30·max(0, 상체 하강) )       ← 전진 쪽으로만
```

**핵심 원칙: 방향은 가장 신뢰할 수 있는 신호 하나만 정하고, 나머지는 증폭만 한다.**

- **얼굴·주먹의 어깨선 대비 상하 이동**만 방향을 결정한다. 몸통이 돌아도 거의 변하지 않아 가장 안정적이다.
- **상체 하강**은 앞으로 숙이든 뒤로 젖히든 똑같이 내려가므로 방향을 못 정한다.
  전진에서 가장 큰 신호이므로 **증폭에만** 쓴다 → 전진엔 주력으로 실리고 후진 기여는 정확히 0.
- **어깨폭(카메라 거리)** 은 몸통 회전(yaw)만으로도 줄어든다. 어깨를 넣어 펀치하면 "멀어짐"으로 읽혀
  뒤로 밀린다. 그래서 얼굴·주먹이 동의할 때만 기여시킨다.
- 길이 단위도 순간 어깨폭이 아니라 **평활된 값**을 쓴다. 순간값을 분모로 쓰면 몸통 회전 시
  얼굴·주먹 비율까지 부풀려져 방향 판정이 오염된다. 추종은 **커질 때 빠르게 / 작아질 때 느리게**
  (회전은 폭을 줄이기만 하므로 이 비대칭이 회전 오염만 골라 걸러낸다).
- 이 세 가지를 다 적용했을 때 깊은 몸통 회전(22% 축소)의 pitch가 **−0.13 → −0.01** 로 떨어진다
  (후진 임계 −0.12).
- 전진 임계 `0.16/0.10`, **후진 `0.12/0.07`** — 사람은 뒤로는 조금밖에 못 젖히므로 비대칭으로 잡는다.
- HUD에 `pitch = face + fist + body + near` **항별 내역과 필요 임계값이 상시 표시**되므로,
  임계값 조정 시 어느 항이 부족한지 바로 확인할 수 있다.
- **회전은 앞/뒤/좌/우와 완전히 독립된 상태 머신**입니다. "앞으로 숙이면서 왼쪽으로 회전"이 동시에 성립합니다.
  반대로 좌/우 스텝(어깨 기울임)과 회전(어깨 평행)은 전제가 상충하므로 서로 섞이지 않습니다.
- 민감도 억제: EMA 평활(α=0.35) → 히스테리시스 → **연속 3프레임 투표** 후에야 상태 확정.

### 2-2. 공격 · 방어 모션

펀치 운동학은 `poseWorldLandmarks`(**미터 단위 3D**, 골반 중심 원점)로 계산합니다.
정면 펀치는 화면상에서 팔이 짧아 보이므로(foreshortening) 2D 좌표만으로는 뻗음을 판별할 수 없습니다.

| 모션 (Action) | 발동 동작 | 판정 근거 | 데미지 | 사거리 |
| :--- | :--- | :--- | :---: | :---: |
| **LEFT_JAB** | 왼팔을 정면으로 빠르게 뻗음 | 궤적에 상·측면 성분이 적음 | 5 | 10 |
| **RIGHT_CROSS** | 오른팔을 정면으로 빠르게 뻗음 | 〃 | 6 | 10 |
| **LEFT_HOOK / RIGHT_HOOK** | 팔을 접은 채 **옆에서 안쪽으로** 휘두름 | `\|vx\|/speed > 0.56` ∧ 팔꿈치 < 158° | 7 | 10 |
| **LEFT_UPPERCUT / RIGHT_UPPERCUT** | 팔을 접은 채 **아래 → 위**로 올려침 | `-vy/speed > 0.55` ∧ 팔꿈치 < 150° | 8 | 8 |
| **DUAL_GUARD** | 양 손목을 어깨선 위 + 얼굴 옆으로 (0.16초 유지) | 양 손목이 `shMidY + 0.15·어깨폭` 위 ∧ 코와의 거리 < 어깨폭 1.0배 | 받는 피해 **80% 감소** | — |
| **ENERGY_WAVE** | 양손을 모았다가 함께 앞으로 밀기 | 손목 간격 < 어깨폭 0.62배 ∧ 양팔 동시 1.1 m/s | 34 | 18 |
| **IDLE** | 기본 스탠스 | — | — | — |

**데미지 설계**: 속도 보너스는 최대 **+25%**(`1 + min(v,50)/200`). 가장 센 어퍼컷을 최고 속도로
맞아도 10이라, **HP 100은 최소 10대를 버팁니다** (필살기 제외 — 그건 게이지를 채워야 쓰는 별개 축입니다). 잽/스트레이트 위주의 실제 대전에서는 15~20대가 오갑니다.
가드는 받는 피해를 80% 줄입니다(`×0.2`).

### 필살기 `ENERGY_WAVE` — 분노 게이지가 가득 찰 때만

| 항목 | 값 |
| :--- | :--- |
| **발동 조건** | 분노 게이지 **100/100** (약 9대 맞으면 가득) |
| **동작** | **양손을 머리 위로 번쩍 들고 0.35초 유지** |
| **데미지** | **34** (가드해도 절반인 17만 막힙니다) |
| **사거리 / 각도** | 18 units · dot 0.1 (정면 약 ±84° 부채꼴) |
| **대상** | **부채꼴 안의 모두** — 일반 펀치는 가장 정면인 한 명만 |
| **소모 / 쿨다운** | 게이지 전부 소모 · 1.2초 |

처음에는 "가슴에 모았다가 앞으로 밀기"였는데 실사용에서 인식이 잘 안 됐습니다. 밀어내는 순간의
속도와 뻗음을 동시에 요구하다 보니 자세가 조금만 어긋나면 놓칩니다. 손가락 랜드마크를 쓰면 더
정교하겠지만 Pose와 Hands를 병용해야 해 FPS가 무너집니다.

그래서 **속도를 요구하지 않는 정적 자세**로 바꿨습니다. 세 조건을 동시에 만족한 채 0.35초만
있으면 되고, **천천히 들어도 걸립니다.**

| 조건 | 값 | 무엇과 구분되는가 |
| :--- | :--- | :--- |
| 손목이 코보다 위 | 어깨폭 **0.28배** 이상 | 가드는 턱 높이가 최대 — 복싱 중 절대 안 나오는 자세 |
| **양손 모두** | — | 한 손 펀치·훅 |
| 팔이 펴짐 | 어깨폭 **0.72배** 이상 | 머리를 감싸는 동작(팔꿈치 접힘) |

자세를 잡는 동안 HP 바 아래 게이지에 `⚡ 필살기 충전 nn%` 가 표시됩니다.

### 분노 게이지 (RAGE)

맞을수록 찹니다. **지고 있는 쪽에 역전 수단**을 주어 경기가 끝까지 팽팽하도록 한 장치입니다.

| 획득 | 값 |
| :--- | :--- |
| 맞았을 때 | 데미지 1당 **2.2** (한 대에 약 13 → **7~9대면 가득**) |
| 때렸을 때 | 데미지 1당 **0.55** — 적극적으로 싸우는 쪽도 손해 보지 않게 |
| 감쇠 | 초당 **1.2** — 단 **가득 찬 게이지는 식지 않습니다** |

> 가득 찬 게이지까지 감쇠시키면 100에 닿는 순간부터 곧바로 깎여(실측 99.1)
> 사용 조건을 영영 만족하지 못합니다. 어렵게 채운 게이지는 쓸 때까지 유지됩니다.

**화면 표시**: 게이지가 차오르면 아바타 몸에서 **불꽃 오라**가 일고, 가득 차면 붉은 주황에서
**흰 노랑으로** 바뀌며 회전이 빨라집니다. 조작 없이 "지금 쓸 수 있다"가 보입니다.
1인칭 HP 바 아래 게이지 막대에도 `⚡ 필살기 준비` 가 뜹니다.

**아바타 모션**: 기술마다 궤적이 다릅니다 (`static/humanoid.js`의 `punchPose`).
스트레이트는 팔꿈치를 펴며 곧게 뻗고, 훅은 팔꿈치를 90°로 접은 채 바깥에서 안쪽으로 감아치며
(어깨 z회전 69° 스윙), 어퍼컷은 무릎을 낮췄다가 팔을 가장 높이 들어올립니다.
치지 않는 팔은 가드를 유지하므로 어느 팔로 쳤는지가 선명합니다.

**발동 방식 — 창(window) 래치**: 펀치 신전 구간은 0.15초 안팎이라, 여러 조건을 한 프레임에서
동시에 만족하도록 요구하면 **속도가 최고인 프레임은 아직 덜 뻗었고 / 다 뻗은 프레임은 이미 감속**해서
놓치게 됩니다. 그래서 조건을 시간 창에 걸쳐 누적합니다.

1. 팔이 빠르게 뻗기 시작하면 창을 연다 — `손목 속도 > 1.0 m/s` ∧ `뻗음 증가율 > 0.40 m/s`
2. 창(**380ms**) 동안 **최고 속도와 그 순간의 궤적 방향·팔꿈치 각도**를 기록한다
3. 조건이 차면 발사 — `최고 속도 ≥ 1.6 m/s` ∧ (`뻗음 ≥ 어깨폭 0.88배` **또는** 창 시작 대비 `+0.28배`)

쿨다운은 같은 팔 400ms / 양팔 200ms. 종류 분류는 **최고 속도 순간의 속도 벡터와 팔꿈치 각도**로 하므로
감속 구간에서 엉뚱하게 분류되지 않습니다. 거리는 전부 어깨폭 배수라 체격이 달라도 같은 값이 통합니다.

> **잽 기준으로 맞춰져 있습니다.** 잽은 리치가 어깨폭 0.9배 남짓, 신전 시간 0.11초 안팎이라
> 스트레이트 기준(예전 `속도 2.0 / 뻗음 0.95`)으로는 걸리지 않았습니다. 대신 완화하면 비스듬한 잽이
> 훅/어퍼로 새기 쉬우므로 **분류 임계는 반대로 올렸습니다**(훅 0.50→0.56, 어퍼 0.48→0.55).
> 실제 훅/어퍼는 0.78~0.80이라 여유가 충분합니다.

또한 양 손목이 같은 방향·비슷한 속도로 움직이면 회전 제스처로 보고 펀치를 발동하지 않습니다
(**펀치는 한쪽 팔만 빠르다**). 팔별로 독립 판정하므로 **반대쪽 팔이 가려져도 치는 팔은 인식**됩니다.
가드 중이라도 한쪽 팔이 뻗어 나가면 펀치로 봅니다 — 복싱 스탠스는 상시 가드에 가깝기 때문에
가드로 펀치를 막으면 스탠스를 제대로 잡은 사람이 오히려 못 칩니다.

**펀치 잠금**: 펀치는 몸통 회전(투영 어깨폭 축소)과 주먹 이동을 동반해 자세 신호를 크게 흔듭니다.
그래서 발동 후 **최소 180ms**(팔이 아직 나가 있으면 최대 1100ms까지 연장) 동안 자세 신호를 **얼립니다**.
이 구간에는 **새 이동 방향이 생기지 않지만, 잠금 직전의 이동 의사는 유지**됩니다 —
잽을 뿌리며 전진하는 동작이 되고, 펀치가 나를 밀 수는 없습니다.

**분류 파이프라인**: `MediaPipe Pose (7 nodes)` → `어깨폭 정규화 자세 특징 + 미터 단위 팔 운동학`
→ `히스테리시스 · 프레임 투표 상태 머신` → 서버 판정.
학습된 BiLSTM(`motion_learning/boxing_lstm.pth`, 6-class)은 손 랜드마크 63차원 입력 기준이라
현재 파이프라인과 입력 규격이 다릅니다. 런타임 연동은 TODO (`TODO.md` #1).

## 🕹️ 5. 상세 조작 가이드 (Control Guide)

### Fighter (웹캠 클라이언트)

> **접속 직후 ~2초간 기립 스탠스로 가만히 서 있으세요.** 이 자세가 중립 기준으로 기록됩니다.
> HUD에 `CAL 30/30` → `OK`로 바뀌면 준비 완료. 자세가 틀어지면 **`C` 키로 재보정**.

**🏃 이동 (몸 기울임)** — 상반신 전체를 씁니다. 손만 움직이면 반응하지 않습니다.

| 하고 싶은 것 | 몸 동작 | 비고 |
| :--- | :--- | :--- |
| 전진 | **어깨를 수평으로 유지한 채** 앞으로 숙이기 (얼굴·주먹이 아래로) | 후진보다 쉽게 걸립니다 |
| 후진 | **어깨를 수평으로 유지한 채** 뒤로 젖히기 (얼굴·주먹이 위로) | 속도 0.85배 |
| 좌/왼쪽 스텝 | 왼쪽 어깨를 내려 **어깨선을 기울이기** | 8° 넘게 기울면 앞/뒤는 꺼집니다 |
| 우/오른쪽 스텝 | 오른쪽 어깨를 내려 **어깨선을 기울이기** | 〃 |
| 좌/우 회전 | **어깨는 수평으로 둔 채** 양 주먹을 함께 왼쪽/오른쪽으로 쓸기 | 제스처 1회당 45° |
| 필살기 | **양손을 머리 위로** 번쩍 들고 유지 | 게이지 100 필요 · 0.35초 |

- 회전은 이동과 **독립된 상태 머신**이라 "숙이면서 회전"이 동시에 됩니다.
  반대로 좌/우 스텝(어깨 기울임)과 회전(어깨 평행)은 전제가 상충하므로 섞이지 않습니다.
- 웹캠 화면의 **점선이 어깨 수평 기준선**입니다. 초록 = 평행(전/후진·회전 가능), 빨강 = 기울어짐(좌/우 스텝).
- 오검출 방지를 위해 자세를 **약 0.11초 유지**(`HOLD_ON_MS`)해야 상태가 확정됩니다. 해제는 0.10초.
- **임계값을 1.7배 넘겨 확실하게 기울이면 기다리지 않고 즉시 반응합니다**(`FAST_RATIO`).
  펀치가 빠른 이유가 "확실한 증거는 즉시"라는 경로 덕분인데, 이동에도 같은 경로를 뒀습니다.
  실측 반응 시간 — 크게 숙임 **33ms** / 살짝 숙임 **233ms** (예전에는 둘 다 400~500ms).
- 상태가 확정되면 최소 강도(`MOVE_MIN_INTENSITY` 0.38)가 보장됩니다. 임계값을 갓 넘긴 자세가
  기어가면 "켜졌는데 안 움직인다"가 되어 결국 느리게 느껴집니다.
- 유지 시간·평활(EMA 시상수 0.19초)은 모두 **시간 기준**이라 기기별 포즈 추정 FPS가 달라도 조작 체감이 같습니다.

**🎯 자동 조준** — 서버 타격 판정이 `dot(내 시선, 상대 방향) > 0.3`에 의존하므로 **조준이 곧 명중률**입니다.
회전 제스처만으로는 옆에 선 상대를 겨누기 어려워(1회 45° 상한) 두 단계로 자동화했습니다.

| 단계 | 동작 |
| :--- | :--- |
| **상시 정렬** | 수동 회전 입력이 없으면 가장 가까운 **살아있는** 상대 쪽으로 서서히 돕니다 (원거리 3.0/s · 교전 중 8.0/s) |
| **펀치 스냅** | 펀치가 나가는 **순간** 사거리 11u · ±120° 안의 상대에게 **즉시 정렬**합니다 |

- 수동 회전(제스처 또는 화살표) 직후 **0.5초**는 상시 정렬을 쉽니다.
- 등 뒤(±120° 밖)나 사거리 밖(11u 초과)은 스냅하지 않습니다.
- K.O.된 상대는 조준·자동접근 대상에서 빠집니다.
- HUD 마지막 줄 `Target: P3 6.2u -12deg LOCKED` 로 현재 조준 상태가 보입니다
  (`LOCKED` 오차 14° 이내 · `aiming` 정렬 중 · `manual` 수동 입력 직후).

**👊 공격 · 방어**

| 기술 | 동작 | 데미지 |
| :--- | :--- | :---: |
| 잽 / 스트레이트 | 팔을 정면으로 **빠르게** 뻗기 | 5 / 6 |
| 훅 | 팔을 **접은 채** 옆에서 안쪽으로 휘두르기 | 7 |
| 어퍼컷 | 팔을 **접은 채** 아래에서 위로 올려치기 | 8 |
| 더블 가드 | 양 주먹을 얼굴 옆(어깨선 위)으로 올리고 0.16초 유지 | 받는 피해 80% 감소 |

- **훅·어퍼컷은 팔을 편 채로는 인식되지 않습니다.** 분류가 최고 속도 순간의 팔꿈치 각도를 보므로
  (훅 < 158° · 어퍼 < 150°), 접은 채 휘둘러야 스트레이트와 구분됩니다.
- 같은 팔은 0.4초, 양팔 공통 0.2초 쿨다운이 있습니다.
- 양 주먹이 같은 방향으로 함께 움직이면 **회전 제스처**로 보고 펀치를 내지 않습니다.

**⚡ 필살기 (분노 게이지 100)**
- HP 바 아래 게이지가 가득 차면 `⚡ 필살기 준비` 가 뜨고 **몸에서 불꽃이 흰 노랑으로** 타오릅니다.
- **양손을 가슴 앞에 모아 0.26초 유지** → **함께 앞으로 밀어냅니다.**
- 정면 부채꼴(18u, 약 ±84°) 안의 **모두**를 34씩 때립니다. 가드해도 절반만 막힙니다.

**🎚️ 이동 범위 보정 (권장)**

  ① 기본 스탠스로 가만히 ② 앞으로 최대한 숙이기 ③ 뒤로 최대한 젖히기 (각 2.6초)
- 측정한 최대 기울기의 **45%**가 발동 임계가 됩니다. 사람마다·카메라 각도마다 기울일 수 있는
  정도가 크게 다르므로, 고정 임계값은 누구에겐 너무 빡빡하고 누구에겐 너무 헐렁합니다.
- 브라우저에 저장되어 다음 접속에도 유지됩니다. HUD `need:` 줄에 `[내 범위]` / `[기본값]`으로 표시됩니다.

**🤝 근접 교전 (자동)**

  상대를 향해 빠르게 정렬합니다. 서버 타격 판정이 시야각에 의존하므로 이 정렬이 명중률을 좌우합니다.
- 빠져나오려면 **뒤로 젖히세요** — 후진 중에는 자동 접근이 적용되지 않습니다.

**🥊 펀치 중에는 — 회전만 멈추고, 걷던 방향은 유지됩니다**
- 펀치 발동 후 잠금 구간(`PUNCH_LOCK` **180ms**, 팔이 아직 나가 있으면 `PUNCH_LOCK_MAX` 1100ms까지)
  동안 **회전은 완전히 정지**합니다. 주먹을 좌우로 쓰는 것이 곧 회전 신호라 펀치와 정면으로 겹칩니다.
- 반면 **앞/뒤/좌/우 이동은 잠금 직전의 상태를 그대로 유지**합니다. 잽을 뿌리며 전진하는 동작이 됩니다.
  잠금 중에 **새 이동 방향이 생기지는 않으므로**, 펀치가 나를 뒤로 밀 수는 없습니다.
- 이 구간에는 **자세 신호(roll·pitch·어깨폭) 자체를 갱신하지 않고 얼립니다.** 적용만 막으면,
  펀치의 몸통 회전으로 흔들린 값이 잠금이 풀리는 순간 그대로 튀어나가 뒤/옆으로 밀립니다.

> 이전에는 잠금 중 이동을 **완전히** 막았는데, 실제 연타 간격(0.20~0.30초)이 당시 잠금 하한(480ms)보다
> 짧아 **잠금이 한 번도 풀리지 않아 웹캠 이동이 아예 불가능**했습니다 (8차 피드백, `DEVLOG.md` 참조).
> 키보드 `↑`는 잠금과 무관하게 항상 동작합니다.

**📸 얼굴 등록 (3D 복원)**
- 헤더의 **📸 얼굴 등록** 버튼 → 가이드 원에 얼굴을 맞추고 **촬영 시작**.
  정면 여부와 얼굴 크기를 실시간으로 검사하므로, 조건이 맞을 때만 12프레임을 모읍니다.
- MediaPipe **Face Mesh 468개 랜드마크**로 그 자리에서 3D 얼굴 메쉬(852 삼각형)를 복원하고,
  **얼굴 테두리(FACE_OVAL 36점)에서 뒤통수를 만들어 붙여 닫힌 머리**(약 1400 삼각형)로 완성합니다.
  앞·옆·뒤 어디서 봐도 머리로 보입니다. 다른 파이터·host 화면에도 같은 얼굴로 보입니다.
- **맞으면 그 자리가 눌리고 멍이 누적**되며, **HP가 낮아지면 코피가 나고 지친 표정**으로 바뀝니다
  (눈썹 처짐 · 눈 반쯤 감김 · 입 벌어짐 · 부기).
- Face Mesh 는 **촬영 순간에만** 돌고 즉시 꺼집니다. 게임 중에는 Pose 만 돌아 FPS 영향이 없습니다.
- 안경·모자는 벗는 편이 정확합니다. 얼굴 데이터는 서버 메모리에만 있고 디스크에 저장되지 않습니다.

## 📊 8. 정확도 벤치마크 (eval/)

하니스는 **로직이 의도대로 도는가**를 봅니다. 하지만 "잽을 뻗었는데 잽으로 잡히는가"는
합성 궤적으로는 알 수 없습니다. 그래서 실제 사람이 90초 동안 정해진 순서로 복싱하는 영상을
찍고 **구간별 정답 라벨**을 붙여, 판정기가 몇 개를 맞히는지 잽니다.

### 실행

```
# 저장소 루트에서 (--video/--labels 기본값이 이미 벤치마크 파일을 가리킨다)
python iter3/eval/run_pipeline.py --version <태그이름>
```

`--version` 을 생략하면 `v1_baseline` 을 **덮어씁니다.** 새 실험은 반드시 태그를 주세요.

4단계로 돕니다 — ① MediaPipe 랜드마크 추출 ② 펀치 판정 ③ 라벨 대조 채점 ④ 보고서.
①은 결과를 `video/*_landmarks.jsonl` 로 캐시하므로 두 번째부터는 건너뜁니다.
캐시가 있으면 **영상 디코딩이 필요 없으므로 opencv·mediapipe 없이도 채점이 돕니다**
(mediapipe 는 Python 3.13 휠이 아직 없다). 이를 위해 두 모듈은 영상 경로에서만 지연 로딩합니다.

### 현재 성적 (benchmark.mp4, 정답 29개)

| 지표 | 값 |
| :--- | ---: |
| 검출 | 59개 |
| TP / FP / FN | 17 / 42 / 12 |
| 정밀도 | 0.288 |
| 재현율 | 0.586 |
| **F1** | **0.386** |
| 기술 종류 정확도 | 0.235 |
| 좌우 정확도 | 0.471 |
| 타이밍 오차(평균) | 111.9 ms |

### 합성 데이터는 만점이 나옵니다

같은 판정기를 합성 궤적 11케이스(`eval/datasets/`)에 돌리면 이렇습니다.

```
python iter3/eval/run_suite.py
```

| | 합성 11케이스 | 실영상 90초 |
| :--- | ---: | ---: |
| 정답 / 검출 | 68 / **68** | 29 / **59** |
| 정밀도 | **1.000** | 0.288 |
| 재현율 | **1.000** | 0.586 |
| F1 | **1.000** | 0.386 |
| 기술 종류 정확도 | **1.000** | 0.235 |

**합성 궤적을 넣으면 그 궤적에 맞춰 만든 임계값이 당연히 맞습니다.** 회귀 검사로는 쓸모가
있지만(튜닝을 바꿔 뭔가 깨지면 여기서 먼저 걸립니다) 정확도의 근거로는 쓸 수 없습니다.
실제 사람의 영상이 필요했던 이유입니다.

### 실영상에서 무엇이 문제인가

**정밀도가 문제입니다** — 29개를 맞히려고 59개를 쏘고 있습니다. 구간별로 보면 원인이 뚜렷합니다.

| 구간 | 성격 | 검출 |
| :--- | :--- | ---: |
| 직선 펀치 06~18s | 동작 | 5 |
| 훅 23~35s | 동작 | 17 |
| 어퍼컷 40~52s | 동작 | 15 |
| **풋워크 57~70s** | **비동작** | **9** |
| 숨고르기 4구간 | 비동작 | 2 |

**풋워크 구간에서 9번 헛나갑니다.** 스텝을 밟으면 상체가 흔들리는데, 어깨 기준 손목 속도로는
이것이 뻗음과 구분되지 않습니다. 훅·어퍼 구간의 17·15도 정답 대비 과검출이라 한 번 뻗을 때
여러 번 발사되는 것으로 보입니다. 게임에서 체감이 나쁘지 않은 이유는 **과검출이 "잘 나간다"로
느껴지기 때문**이고, 이 표는 그 체감이 정확도가 아니라는 것을 보여줍니다.

### 남은 이중 유지보수

`eval/evaluate_video.py` 는 판정 상수를 **자기 파일에 복사해서** 갖고 있습니다.
현재 펀치 상수 12개는 `punch_core.js` 와 전부 일치하지만, 자동으로 따라가는 것이 아니라
사람이 맞춰 둔 것입니다. 같은 폴더의 `evaluate_full_actions.py` 는 실제로 어긋나 있습니다 —
자세·이동 상수 12개가 옛 값이고 필살기 판정이 통째로 없습니다(현재 아무 곳에서도 호출하지 않음).

근본 해법은 평가기가 Node 로 `punch_core.js` 를 직접 실행하는 것입니다. 그러면 런타임 튜닝을
고치는 순간 점수가 따라 움직입니다. `punch_core.js` 를 브라우저·Node 공용으로 만들어 둔 이유가
이것입니다.

### 브라우저 하니스가 안 돌 때

`tests/_cdp.js` 는 **환경변수 → 플랫폼별 표준 경로 → `PATH` 탐색** 순으로 브라우저를 찾습니다.
Windows·macOS·Linux 경로가 모두 들어 있지만, 컨테이너는 설치 위치가 제각각입니다.

```bash
CHROME_PATH=/usr/bin/chromium node page_harness.js
```

브라우저가 아예 없으면 **로직 하니스 7종만 돌리면 됩니다.** 다만 그 7종이 전부 통과해도
페이지가 검은 화면일 수 있다는 점은 기억해야 합니다 — 실제로 `fx` 이름 충돌이 그랬습니다.
브라우저를 못 쓰는 환경에서 렌더 경로를 건드렸다면, **머지 전에 로컬에서 4종을 한 번 돌리세요.**

### 서버는 뜨지만 플레이는 안 됩니다

`getUserMedia` 는 웹캠을 요구하고, 브라우저가 카메라를 열지 못하면 파이터 화면은 보정
마법사에서 멈춥니다. 웹에서 렌더 쪽을 확인하고 싶다면 브라우저 하니스가 쓰는 방식을 그대로
쓰면 됩니다 — Chrome 의 `--use-fake-device-for-media-stream` 으로 가짜 카메라를 물립니다
(`tests/_cdp.js` 의 `fakeMedia` 옵션).
